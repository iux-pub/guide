구현 전후의 디자인 리뷰에 쓰는 감사 체크리스트. 17개 카테고리로 화면을 점검하고 고칠 순서를 정한다.

> **정본 관계** — KRDS(컴포넌트·패턴·타이포그래피 지침) → `contracts/art-direction.json`(MCP `get_art_direction`)·`contracts/profiles.json`(`get_profile`) → 이 문서. 충돌하면 앞선 것이 이긴다. 이 문서의 표와 예시는 참고 자료다.

## 감사 범위 선택

| 범위 | 카테고리 수 | 용도 |
|------|------------|------|
| **풀 감사 (Full)** | 17개 전체 | 신규 화면/컴포넌트 최종 검수 |
| **빠른 감사 (Quick)** | 5개 핵심 | 타이포, 색상, 간격, 접근성, 상태 |
| **커스텀** | 선택 | 특정 카테고리만 집중 점검 |

메인·랜딩 페이지의 시각 품질은 이 체크리스트로 채점하지 않는다. `references/design-intelligence.md` §8 렌더 비평을 쓴다 — 점수 대신 별도 평가자의 결함 문항(예·아니오)과 짝 비교, 그리고 사람 판정으로 본다.

## 점수 체계

100점에서 시작해 이슈마다 차감한다. 점수는 고칠 순서를 정하는 참고값이다.

| 심각도 | 차감 | 기준 |
|--------|------|------|
| **Critical** | -8점 | 사용성/접근성을 깨뜨리는 문제 |
| **Warning** | -4점 | 디자인을 약화시키는 문제 |
| **Tip** | -1점 | 다듬기 수준의 개선 사항 |

출시 여부는 점수가 아니라 `references/release-checklist.md`의 관문으로 정한다.

| 구분 | 항목 | 기준 |
|------|------|------|
| 필수 | 접근성 · 과업 흐름 · 품질 | 100% — 하나라도 미달이면 배포하지 않는다 |
| 권장 | 목적 · 신뢰 · 일관성 · 인수인계 | 전체 합산 85% 이상 |

Critical 이슈가 남아 있으면 필수 항목 미달로 본다.

## 17개 감사 카테고리

### 1. 타이포그래피

- [ ] 서체는 토큰으로만 쓴다 -- 본문 `--font-sans`, 제목 `--font-heading`(카탈로그 페어링 1종까지), 고정폭 `--font-mono`
- [ ] 크기는 KRDS 타이포 단계만 쓴다 -- 본문 1.7rem, 1.3rem 미만 없음(R-38)
- [ ] 계층 명확 -- h1 > h2 > h3 > 본문의 크기 차이가 보인다. 한 화면의 글자 크기는 다섯 가지 이하
- [ ] 행간 -- 본문 1.6~1.7, 제목 1.5. 모든 텍스트 150% 이상(R-24)
- [ ] 자간 -- 음수 자간 없음. 본문 자간 0
- [ ] 본문 줄 길이 28~42자(한글, 공백 포함). 게시판 목록·약관·표는 예외
- [ ] 본문은 왼쪽 정렬, `word-break: keep-all`
- [ ] 텍스트 대비율 4.5:1 이상

### 2. 색상 & 대비

- [ ] 모든 텍스트: 4.5:1 이상 (AA 기준), 큰 텍스트 3:1 이상
- [ ] UI 요소(버튼 테두리, 아이콘): 3:1 이상
- [ ] 색만으로 상태를 표현하지 않음 -- 글자나 아이콘을 함께 쓴다
- [ ] 색은 전부 `var(--color-*)` 토큰 -- 하드코딩 없음(R-01)
- [ ] 장식 그라데이션·글래스·색 글로 없음(R-34)

### 3. 간격 & 레이아웃

- [ ] 간격·크기는 rem 직접값 -- Tailwind 기본 스케일(`p-4`, `gap-2`) 없음(R-37)
- [ ] 간격은 세 종류 -- 묶음 안, 묶음 사이, 섹션 사이. 섹션 여백은 밀도 프리셋을 따른다(R-49)
- [ ] 관련 요소는 가깝게, 무관한 요소는 떨어뜨린다
- [ ] 같은 컴포넌트의 안쪽 여백이 화면마다 같다
- [ ] 텍스트/아이콘 정렬 축 일치

### 4. 시각 위계

- [ ] 주 행동(Primary)이 가장 눈에 띈다
- [ ] 화면을 흐리게 봐도 1·2·3순위가 차례로 보인다
- [ ] 크기/대비/간격이 중요도 순서와 일치

### 5. 일관성

- [ ] 같은 목적의 컴포넌트가 같은 규격을 쓴다
- [ ] 아이콘은 카탈로그 한 세트, 한 표정
- [ ] 반경 1.2rem 이하, 알약 버튼 없음(R-35)
- [ ] 한 페이지의 카드·패널 처리는 두 가지 이하

### 6. 접근성

- [ ] 터치 영역 44x44px 이상 (R-13)
- [ ] 모든 인터랙티브 요소에 초점 상태가 있다 -- 전역 초점 링(0.4rem, `--color-border-primary`)을 지우지 않았다
- [ ] 폼 레이블 연결 (보이는 레이블, placeholder로 대신하지 않음)
- [ ] 오류 메시지가 색 말고 글자로도 전달된다
- [ ] 읽기 순서가 시각 순서와 일치
- [ ] 건너뛰기 링크가 문서의 첫 요소다

### 7. 폼 & 입력

- [ ] 레이블 → 보조설명 → 입력 → 시스템 메시지 순서(KRDS)
- [ ] 입력 높이 4.8rem 기본(`input--small` 4rem은 마우스 중심 화면에만)
- [ ] 필수 필드 표시 (`*` + `required`)
- [ ] 유효성 검사 시점: blur(형식) / submit(필수)
- [ ] 오류 메시지: 필드 아래, 「무엇이 잘못됐는지 + 어떻게 고치는지」
- [ ] 개인정보 수집 폼 -- 동의 옆에 목적·항목·보유 기간·거부권, 미리 체크 없음(R-47)

### 8. 모션 & 애니메이션

- [ ] 사용자 동작에 답하는 전환 150~250ms
- [ ] 장식·스크롤 진입 모션은 표현 등급 상한 안(기능형 200·절제형 300·표현형 400ms), 500ms 초과 없음(R-22)
- [ ] 의도한 등장 효과는 페이지에 하나 -- 모든 섹션 등장 효과 없음(R-51)
- [ ] 무한 반복은 로딩 표시뿐. 자동 재생 영상 없음, 자동 전환에는 정지 버튼(R-33)
- [ ] `prefers-reduced-motion` 대응

### 9. 색 모드

- [ ] infoUX는 light·high-contrast 두 모드 체계다 -- 요구에 없는 다크 모드 토글을 만들지 않았다
- [ ] 브랜드 색을 바꿨으면 두 모드 값을 모두 정의하고 `npm run check:contrast`를 통과했다
- [ ] 짙은 면 위의 부품(버튼·선·초점 링)을 그 면에 맞췄다

### 10. 반응형 디자인

- [ ] 모바일 우선 작성
- [ ] 360 · 768 · 1024 · 1280px에서 확인 (넓은 화면은 1440 추가)
- [ ] 가로 스크롤 없음 (360px)
- [ ] 본문 1.6rem 이상, 루트 글자 크기 62.5% 유지(R-31·R-38)
- [ ] 테이블: 모바일에서 `table-wrap` 가로 스크롤 또는 목록 변환
- [ ] 1024px에서 메인 메뉴와 전체메뉴가 바뀐다

### 11. 상태 (States)

- [ ] 로딩 상태 (`spinner` / `progress`)
- [ ] 빈 상태: 사실 문장 제목, 다음 행동이 있으면 버튼
- [ ] 오류 상태: 수준별 처리 (필드 메시지 / `alert` / `error-page`)
- [ ] 성공 상태: `toast` 또는 `alert`
- [ ] 비활성 상태: `disabled` 속성 + 비활성 토큰, 이유를 알 수 있다
- [ ] 컴포넌트별 상태 셋을 실물로 확인했다([UI 상태 패턴](/design/ui-states/))

### 12. 마이크로카피

- [ ] 버튼 레이블: 동사형(KRDS). 명사형은 완료·닫기·취소·추가·삭제 같은 일반 작업만
- [ ] 문체: 합쇼체 사실 서술. 해요체·번역투·느낌표 없음(R-43·R-44)
- [ ] 오류 메시지: 3파트 공식 (무엇이 / 왜 / 어떻게)
- [ ] placeholder: 레이블을 대신하지 않고 예시만(R-50)
- [ ] 용어 일관성: 같은 개념에 같은 단어
- [ ] 가짜·자리 콘텐츠 없음(R-23), 링크마다 실제 목적지(R-30)

### 13. 다국어

- [ ] `html`에 `lang` 속성(R-21)
- [ ] 언어 링크는 그 언어의 원어 레이블과 같은 `lang`을 갖는다(R-45)
- [ ] 한국어 화면에 영문 전용 UI 레이블이 없다(R-45)

### 14. 엘리베이션 & 그림자

- [ ] 그림자는 KRDS 3단계 검정 알파(shadow1·2·3 = 5·8·12%) 조합만 사용 — 색 있는 글로우 그림자 없음 (R-34)
- [ ] 그림자는 떠 있는 요소(드롭다운, 모달, 토스트)에만 쓴다
- [ ] 그림자 blur 2.4rem 이하(R-35)

### 15. 아이콘그래피

- [ ] 아이콘은 카탈로그 스프라이트에서 가져온다(R-27)
- [ ] 아이콘 크기: 16 / 20 / 24 / 32 / 40px (`.icon--xsmall`~`.icon--xlarge`)
- [ ] 한 제품에서 표정(슬림·레귤러·볼드·필) 하나
- [ ] 인터랙티브 아이콘의 터치 영역 44x44px 이상
- [ ] 보이는 레이블이 기본. 아이콘만 쓰면 접근 가능한 이름(`aria-label`)이 있다
- [ ] 아이콘을 원·사각 배경에 넣어 같은 크기로 늘어놓지 않았다
- [ ] 이모지를 아이콘으로 쓰지 않았다(R-36)

### 16. 내비게이션 패턴

- [ ] 현재 위치 표시 (`aria-current="page"`)
- [ ] 메인 메뉴는 클릭·Enter·Space로 연다 -- 마우스오버로 열지 않는다(KRDS)
- [ ] 탭은 같은 맥락의 병렬 보기에만, 6개 이하. 형제 페이지 이동에 쓰지 않는다
- [ ] 3단계 이상 깊이: 브레드크럼 제공(R-41)
- [ ] 공공 화면은 모든 페이지 헤더에 통합검색(R-40)
- [ ] 푸터에 「개인정보 처리방침」 링크(R-32)

### 17. 디자인 토큰 & 변수

- [ ] 색 하드코딩 없음 (`var(--color-*)`)
- [ ] 서체는 `--font-*` 토큰으로만(R-26)
- [ ] 간격·크기·반경·그림자·모션은 토큰이 아니라 직접값 -- rem 임의값(`p-[2.4rem]`)
- [ ] 프로젝트가 고친 토큰 파일은 `tokens/brand.json` 하나다
- [ ] 의미 토큰 사용 (`--color-surface`, `--color-text`) -- 단계 색(`--color-gray-20`)은 예외일 때만

## Quick 5 -- 납품 전 최소 점검

모든 납품에서 확인하는 다섯 항목.

- [ ] 텍스트 대비율 4.5:1 이상
- [ ] 인터랙티브 요소에 호버·초점 상태가 있다
- [ ] 색 하드코딩 없음 (`var(--color-*)`)
- [ ] 터치 영역 44px 이상
- [ ] 로딩·빈·오류 상태를 만들었다
