# 디자인 판단 절차 — 규칙을 지킨 무개성을 넘어서

규칙 검사를 통과한 화면이 여전히 「구린」 이유는 두 가지다. 하나는 판단 순서를 건너뛴 것이고, 다른 하나는 모델이 습관처럼 붙이는 템플릿 장식이다. 이 문서는 어떤 LLM이 작업해도 같은 수준이 나오도록 구현 전 계획, 자가 점검, 렌더 비평의 순서를 정한다.

> 출처 — 세 스킬을 infoUX 맥락으로 옮겨 다시 썼다.
> - ui-ux-pro-max(Next Level Builder, MIT, 28327f2): 판단 순서, 다이얼, 우선순위 표
> - Impeccable(Paul Bakaus, Apache 2.0, 5cb95ee): craft floor, 템플릿 서명 목록, 색 전략, 렌더 검증
> - Anthropic frontend-design(claude-plugins-official, 465f093): 소재 근거, 2단계 계획과 자가 점검, 「과감함은 한 곳에」, 문구 원칙
>
> **KRDS와 infoUX 규칙(rules.json)이 언제나 우선한다.** 애매하면 KRDS를 따른다.

## 0. 한국 공공 메인 보정 — 해외 기준을 그대로 쓰지 않는다

위 세 스킬은 해외 제품·랜딩 페이지를 기준으로 한다. 그래서 「절제」「한 곳만 과감」「덜어내기」를 강하게 권한다. 이것을 한국 공공기관 메인에 그대로 적용하면 흰 바탕과 가는 선만 남은 관리자 화면처럼 된다(2026-10-23 제주관광공사 시안에서 실제로 퇴보함, 오너 판정). 한국 공공기관 발주처와 이용자는 **풍성하고 예쁜 메인**을 선호한다. 과감한 것도 싫어하지 않는다.

메인·랜딩(pageType main)에서는 아래가 기본값이다. 서브·폼·게시판은 그대로 절제한다.

- **사진을 넉넉히:** 대상의 실사 사진을 여러 장 쓴다. 첫 화면 사진 한 장으로 끝내지 않는다. 주요 사업·명소는 사진 카드나 벤토로 보여 준다.
- **색 면 리듬:** 흰 바탕만 이어 쓰지 않는다. 브랜드 연한 면 띠와 짙은 면 띠를 번갈아 넣어 단원을 만든다(art-direction §5 배경 리듬 안에서).
- **크기가 다른 칸:** 균등한 목록보다 크기가 다른 사진 칸(벤토)과 행동 칸으로 시선을 끈다.
- **덜어낼 것은 「템플릿 서명」(§4)과 군더더기 문구뿐이다.** 사진·색 면·칸 구성을 「장신구」로 보고 빼지 않는다.
- 「과감함은 한 곳에」(§2-4)는 메인에서 「가장 강한 요소 하나를 정한다」로 읽는다. 나머지 섹션을 밋밋하게 두라는 뜻이 아니다.

## 1. 산출물: 디자인 계획

페이지(메인·랜딩·주요 서브)를 만들기 전에 아래 다섯 칸을 채운 디자인 계획을 Task Contract 옆에 남긴다. 파일은 `docs/design-plan.md`로 둔다. 계획 없이 쓴 코드는 납품 전 리뷰에서 되돌린다.

| 칸 | 쓸 것 | 분량 |
|----|-------|------|
| 소재 | 대상의 산업·풍경·재료·관습에서 뽑은 시각 재료 5~7개와, 그중 이 페이지가 쓸 1~2개 | 7줄 이내 |
| 색 | 색 전략 하나(§3)와 역할별 토큰 4~6개. 쓰는 이름은 프리셋 토큰 이름이다 | 6줄 |
| 서체 | 카탈로그 페어링과 역할(제목·본문·숫자), 크기 단계 | 3줄 |
| 레이아웃 | 섹션마다 한 줄 설명과 ASCII 와이어프레임, 정렬(왼쪽·가운데) | 섹션당 3~6줄 |
| 원칙 | 이 페이지에만 해당하는 원칙 2~3개와, 기억에 남을 요소 하나(§2-4) | 4줄 |

### 소재 칸 예시(제주관광공사)

```
현무암(구멍 난 짙은 회색) · 돌담(불규칙한 쌓기) · 감귤(진한 주황) · 갈옷 감물(적갈색)
오름 능선(완만한 곡선) · 제주 바다(청록에서 남색) · 유채(노랑)
→ 쓸 것: 현무암 + 제주 바다. 짙은 현무암 면 위에 바다색 사진, 감귤은 강조 한 곳에만
```

소재는 장식 모티프가 아니다. 팔레트·면 구성·사진 톤을 정하는 근거다. 돌담 무늬를 배경에 깔라는 뜻이 아니다.

## 2. 절차

### 2-1. 근거부터
제품 유형(프로필)과 1순위 과업을 정한다(`project-profiles.md`). 다음으로 메인·서브 레시피를 고르고(`korean-web-patterns.md`), 소재 칸을 채운다. 대상의 업종·소재·풍경은 그 대상만의 선택을 만드는 재료다. 같은 공공기관이라도 관광공사와 연금공단은 달라야 한다.

### 2-2. 계획 쓰기
§1의 다섯 칸을 채운다. 레이아웃은 ASCII로 두세 안을 그려 비교한 뒤 하나를 고른다.

### 2-3. 템플릿 자가 점검
계획을 놓고 스스로 묻는다. 「이 계획을 이름만 바꿔 다른 기관에 그대로 써도 되는가?」 된다면 그 칸은 기본값이다. 그 칸을 고치고, 무엇을 왜 바꿨는지 한 줄씩 계획에 적는다. §4의 템플릿 서명이 계획에 하나라도 있으면 지운다.

### 2-4. 과감함은 한 곳에
기억에 남을 요소를 하나만 정한다. 예를 들면 첫 화면 사진의 크기와 자르기, 한 섹션의 색 면, 제목 하나의 크기 같은 것이다. 나머지는 조용하고 규율 있게 둔다. 모든 섹션이 소리를 내면 페이지는 평평해진다.

### 2-5. 구현
계획대로 짓는다. 카탈로그 컴포넌트를 쓰되, 계획한 색·서체 체계를 모든 부품(헤더·버튼·탭·푸터)에 같은 강도로 입힌다. 기본 모양 그대로인 부품이 하나라도 있으면 「조립한 티」가 난다.

### 2-6. 렌더 비평
375·768·1024·1440 렌더를 보며 §5 점검을 한 번에 돌린다. 섹션을 하나씩 훑는다: 빈 공간, 어긋난 윗선, 높이가 다른 두 단, 남는 오른쪽 절반, 내용보다 큰 칸. 고친 뒤 한 번 더 보고 끝낸다(두 번이 상한).

### 2-7. 장신구 하나 빼기
마지막으로 장식 하나를 뺀다. 빼서 나빠지지 않는다면 원래 없어야 했다. 여기서 장식은 정보·구조를 만들지 않는 꾸밈(가는 선 격자, 장식 아이콘, 테두리 같은 것)이다. 한국 공공 메인의 사진·색 면·칸 구성은 장식이 아니다(§0).

## 3. 색 전략

색을 고르기 전에 전략부터 고른다. 색은 화면 단위로 정한다. 중립 바탕에 강조색을 흩뿌리는 방식이 아니라, 한 색이 넓은 면을 맡는 방식이다.

| 전략 | 정의 | infoUX에서 |
|------|------|-------------|
| 절제(Restrained) | 중립 바탕 + 강조 하나 | 기능형·서브 페이지 기본 |
| 몰입(Committed) | 한 가지 짙은 색이 화면의 30~60%를 맡는다 | 공공기관·관광 메인 권장. primary 70~90 단계 면, 흰 글자 대비 실측 |
| 풀 팔레트(Full) | 이름 붙은 역할 3~4색 | 표현형. primary·secondary·point 토큰만 |
| 범람(Drenched) | 화면 자체가 그 색 | 캠페인 페이지 한정, 예외 기록 필수 |

- 밝은 바탕이냐 어두운 바탕이냐는 업종으로 고르지 않는다. 누가, 어디서, 어떤 빛 아래서 보는지 한 문장으로 쓰고 그 장면으로 정한다.
- 색 면 위 보조 글자는 회색이 아니라 그 면의 색에서 뽑은 밝은 단계로 쓴다.

## 4. 템플릿 서명 — 쓰지 않는다

아래는 AI가 만든 페이지의 흔한 서명이다. 대상과 상관없이 나타나서 「누가 만들었는지」가 보인다. 기계 검출은 R-51(경고)과 R-34·R-36이 맡고, 나머지는 렌더 비평에서 본다.

| 서명 | 대신 |
|------|------|
| 제목 위 분류 표지(eyebrow·kicker)와 그 앞 짧은 색 선 | 제목이 스스로 무게를 갖게 한다. 분류가 필요하면 내비게이션이 말한다 |
| 순서가 아닌 내용의 01·02·03 번호 | 번호는 절차·일정처럼 순서가 정보일 때만. 그때는 `<ol>` |
| 모든 섹션의 페이드·슬라이드 업 등장 | 한 페이지에 의도한 순간 하나. 사용자 동작에 답하는 움직임은 괜찮다 |
| 카드·목록·인용에 굵은 색 옆선(2px 이상) | 면 색이나 여백으로 묶는다 |
| 같은 크기 카드(아이콘+제목+설명)를 페이지 구조로 반복 | 내용에 따라 크기·밀도를 달리한다. 카드 안 카드는 언제나 틀렸다 |
| 큰 숫자 + 작은 라벨 + 보조 통계 히어로 | 대상의 가장 특징적인 것을 첫 화면에 |
| 어두운 스크림 + 가운데 흰 제목 + 스크롤 화살표 히어로 | 사진은 밝게 두고 제목은 사진 밖이나 단색 면에 |
| 링크·버튼 끝의 → | 카탈로그 chevron + `aria-hidden`(R-36) |
| 제목 한 단어만 다른 색·굵게 | 강조는 크기와 굵기 전체로 |
| 영문 대문자 라벨(VIEW MORE, NEWS) | 한국어 동사형(R-45) |
| 메타를 가운뎃점으로 길게 잇기(A · B · C · D) | 필요한 메타 한두 개만, 의미 단위로 배치 |
| 크림 바탕 + 세리프 + 테라코타, 니어블랙 + 형광 강조, 신문식 가는 선·모노 라벨 | 소재 칸에서 나온 색 |

## 5. 렌더 품질 점검 — 규칙 검사가 잡지 못하는 것

### 5-1. 표면 언어
- [ ] 한 페이지의 카드·패널 처리는 두 가지 이하다.
- [ ] 그림자는 KRDS 단계 하나만, 떠 있는 요소에만 쓴다.
- [ ] 아이콘은 한 가족·한 굵기·한 크기 단계다.
- [ ] 헤더·버튼·탭·푸터까지 계획한 색·서체 체계를 입었다. 기본 모양 그대로인 부품이 없다.

### 5-2. 위계와 격자
- [ ] 화면마다 주 행동은 하나다.
- [ ] 섹션 제목과 본문의 크기 비가 2배 이상이다. 비슷한 크기의 굵은 글자가 여러 단계로 흩어지지 않는다.
- [ ] 격자에 빈 칸이 없다. 나란한 두 단은 같은 윗선에서 시작하고 높이가 크게 다르지 않다.
- [ ] 넓은 화면에서 한쪽 절반이 비지 않는다(푸터 포함).
- [ ] 제목 위 여백이 아래 여백보다 크다. 여백 단계는 몇 개뿐이다.
- [ ] 본문 줄길이는 28~42자(art-direction §2)다.

### 5-3. 사진
- [ ] 사이트당 사진 톤은 하나다. 어둡고 탁한 사진을 첫 화면에 두지 않는다.
- [ ] 사진 위 글자는 스크림 위에서 대비를 실측했다.
- [ ] 이미지에 크기 또는 `aspect-ratio`를 주고, 첫 화면 밖은 `loading="lazy"`다.

### 5-4. 상호작용과 브라우저 표면
- [ ] 누를 수 있는 요소는 `cursor: pointer`이고, 호버·초점·누름 상태가 레이아웃을 밀지 않는다.
- [ ] 호버 전환은 150~250ms이고 `prefers-reduced-motion`에서 꺼진다.
- [ ] 브라우저 기본으로 남기 쉬운 표면을 팔레트로 입혔다: 텍스트 선택 색(`::selection`), 링크 밑줄 간격(`text-underline-offset`), 초점 링, 표·날짜 숫자(`tabular-nums`).

### 5-5. 문구
- [ ] 화면의 글은 이해와 사용을 돕는 일 하나씩만 한다. 섹션마다 붙는 설명문은 지운다.
- [ ] 버튼은 무슨 일이 일어나는지 말한다(KRDS 동사형). 같은 동작은 흐름 내내 같은 이름이다.

## 6. 디자인 다이얼

세 다이얼은 표현 등급 안에서 수위를 정한다. 등급(art-direction.md §1)이 상한이다. Task Contract `designDials`에 적는다.

| 다이얼 | 1~3 | 4~6 | 7~10 |
|--------|-----|-----|------|
| 변화도 `variance` | 중앙 정렬, 균등 격자 | 좌정렬, 2:1·1:2 비대칭, 큰 크기 대비 | 겹침·과장된 크기 대비 |
| 모션 `motion` | 상태 피드백만 | 호버 + 의도한 등장 한 번 | 스크롤 연출 |
| 밀도 `density` | 넓은 여백 | 표준 | 촘촘한 목록·표 |

| 등급 | variance | motion | density |
|------|----------|--------|---------|
| 기능형 `utility` | ≤3 | ≤2 | 5~9 |
| 절제형 `restrained` | ≤6 | ≤4 | 4~7 |
| 표현형 `expressive` | ≤8 | ≤6 | 3~7 |

- 한 축만 등급 위로 열 때는 `exceptions[]`에 `expression.layout`·`expression.motion`으로 근거와 만료일을 적는다.
- motion 7 이상과 스크롤 하이재킹·시차는 쓰지 않는다(R-22).

## 8. 우선순위

충돌하면 위가 이긴다. KRDS는 이 표보다 위다.

1. 접근성 2. 터치·상호작용 3. 성능 4. 스타일 일관성(§4·§5-1) 5. 레이아웃·반응형 6. 서체·색 7. 모션 8. 폼·피드백 9. 내비게이션 10. 차트·데이터
