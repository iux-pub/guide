# 한국형 웹 패턴 — 메인·서브·헤더·푸터 기준

국내 웹사이트 96곳을 관찰해 추린 기준이다. 한국형 메인 레시피, 블록 구현 경로, 서브·헤더·푸터 관행을 다룬다. KRDS와 다르거나 애매하면 KRDS를 따른다.

> **정본 관계 — 위가 이긴다**
>
> 1. **KRDS** — 컴포넌트·서비스 패턴·기본 패턴·스타일(타이포그래피·레이아웃) 지침. 원문은 krds.go.kr에 있다. 저장소 사본은 `krds-source.md`(토큰·카탈로그)와 `krds-components.md`(infoUX 카탈로그 대응, `src/snippets`에서 생성)다.
> 2. **contracts·카탈로그** — `profiles.json`(`get_profile`: 등급·밀도·sectionFlow) · `art-direction.json`(`get_art_direction`: 한글 조판 수치) · `class-naming.json`(`get_reference("class-naming")`: 클래스 이름) · `html-page-contract.json`(page shell·section archetype). 카탈로그 정본은 `src/styles/6-components/*.css`와 `src/snippets/*.md`다. KRDS와 다른 곳은 §3.2에 모았다.
> 3. **이 문서** — 메인 레시피(§2. `profiles.json`에 recipes가 들어오기 전까지 임시 정본) · 블록 구현 경로(§3) · 한국 관행 규칙(KP·KR-*) · AI 슬롭 대응(§9)
>
> - 이 문서가 위 정본과 다르거나 애매하면 위 정본을 따르고 이 문서를 고친다.
> - 다른 정본이 가진 수치는 다시 적지 않는다. 링크와 관찰 근거만 둔다.
> - 근거 표기
>   - **KRDS** — KRDS 원문 규정. 관찰 빈도와 무관하게 지킨다.
>   - **infoUX 판단값** — KRDS가 정하지 않아 infoUX가 정한 값. KRDS 규정처럼 인용하지 않는다.
>   - **보통** — 분야군 n이 15 이상인 집계. **근거 약함** — n이 15 미만이거나, 질적 관찰이거나, 범주가 섞인 값.
>   - **재집계** — 2026-10에 원 레코드에서 다시 센 값(고유 96곳). 스크립트 판정과 **재코딩**(저장 원본을 다시 읽어 판정)이 있다.
>   - **1차 집계** — 재집계 대상이 아니었던 첫 코딩 값이다. 중복을 빼지 않은 값은 「97레코드 기준」이라고 적는다. 메인 섹션의 첫 코딩은 **1차 섹션 코딩**이라고 부른다.
>   - **질적 하한** — 사례를 직접 확인한 최소 수. 실제는 더 많을 수 있다.

- **KRDS 표준형** — 정부 상징 로고를 쓰는 중앙행정기관(부·처·청)·특별지방행정기관·부속기관의 대표 웹사이트와 그 밖의 운영 웹사이트. KRDS 스타일을 그대로 적용한다. 제목 페어링·팔레트 교체·expressive 상향을 하지 않는다. `publicIdentity`는 `required`다.
- **KRDS 확장형** — 독자 로고를 쓰는 중앙기관 운영 서비스와 공공기관. KRDS의 색상·타이포그래피·형태·레이아웃·아이콘·엘리베이션 사용 규칙 안에서 기관 특성을 반영한다. 서체는 고딕 계열을 권장한다.
- **지방자치단체**는 KRDS 표준형·확장형 정의 어디에도 없다. 애매하면 KRDS를 따르므로 확장형 규칙을 적용한다. 공식 디지털 정부서비스 여부(`publicIdentity`)는 따로 판정한다.
- 공공 프로필(`public-service`·`public-institution`)은 Task Contract에 KRDS 적용형(`krdsType`)과 `publicIdentity`를 판정해 적고 시작한다. `unconfirmed` 상태로 생성을 시작하지 않는다.
- 운영 주체(재집계): 민간 기업 45, 공공기관 17, 지자체 14, 대학 8, 민간 비영리 7, 중앙부처 5. 공공 운영 36곳.
- 분야군 간 접근성·표현 차이는 출처 구성 차이와 겹친다. 분야 특성으로 단정하지 않는다.

## 2. 메인 페이지 레시피

> - **기록**: 메인 페이지는 Task Contract에 `pageType: main`과 `recipe: <레시피 id>`를 적고, `infoux.json`의 `pageTypes`에도 파일을 `main`으로 선언한다(검사기는 이 선언만 읽는다 — R-40). `cms-admin`은 레시피가 없다 — sectionFlow를 따른다.
> - **우선순위**: `pageType: main`이면 레시피가 프로필 sectionFlow보다 우선한다. 서브·게시판·폼·검색 결과·오류 페이지는 sectionFlow와 §4를 따른다.
> - **순서**: 표의 순서는 판단 기준이다. 순서·구성을 바꾸면 `exceptions`에 근거를 적는다.
> - **근거 열**: 사이트 수는 1차 섹션 코딩을 재집계 분야군으로 다시 묶은 값이다. 위치 중앙값(0=맨 위, 1=맨 아래)은 재집계 값이고, 출현 횟수 기준이라 사이트 수와 n이 다를 수 있다.
> - **R-25**: 같은 archetype이 3연속되지 않게 순서를 조정한다.
> - **archetype 열**: `html-page-contract.json`의 현행 8종이다. 긴급 공지는 `notice-bar` 루트가 그대로 main 직계 section이라 archetype 클래스를 덧붙이지 않는다.
> - `profiles.json`에 recipes가 들어오면(K-08) 이 절의 표는 그 파일에서 생성하는 마커 구간으로 바뀐다. 레시피 id는 `task-contract.schema.json`의 `recipe` enum과 같다.

### 2.0 공통 규칙

| 번호 | 규칙 | 근거 |
|------|------|------|

### 3.0 현재 카탈로그 대체 조합

- 전용 부품이 카탈로그에 들어오기 전에는 아래 조합으로만 만든다(KP-08).
- 표에 적은 BEM 클래스는 `src/styles`에 실재한다. `section`과 `section--{archetype}`은 `html-page-contract.json`이 소유한다(R-29 예외). 표에 없는 element·변형을 붙이지 않는다(R-29).
- 「P1 예정」 부품은 UX팀 결정으로 카탈로그에 들어오면 그 블록으로 바꾼다. 그 이름(quick-links·popup-zone·board-tabs·side-navigation·sub-header·board·language-switcher)을 프로젝트 클래스로 미리 쓰지 않는다 — 반입 때 충돌한다.
- 배치(그리드 열 수·간격)는 카탈로그에 그리드 객체가 없으므로 프로젝트 CSS(`src/styles/project.css`, `init-project`)에서 정한다. 이때도 `class-naming.md` 결정 순서를 따른다. 카탈로그 블록 이름 아래에 element·변형을 새로 만들지 않고, 카탈로그 블록의 모양·동작을 덮어쓰지 않는다. 공통화 가치가 있으면 UX팀에 올린다(`CONTRACT.md` §8).

### 3.1 블록 규칙

#### KS-00 긴급 공지 — `notice-bar`

- **목적**: 서비스 장애·이용 중단 예고·재난처럼 지금 알아야 하는 정보를 본문 맨 위에 보인다.
- **KRDS 규칙**: KR-M00 — main 첫 section, 히어로 앞, 전체 너비, 1개, 닫기·접기 없음, 1줄, 링크는 선택(두면 1개), 필요 기간만 게시.
- **마크업**(main의 첫 section. 정본 `src/snippets/notice-bar.md`)

```html
<section class="notice-bar notice-bar--warning" aria-label="긴급 공지">
  <div class="container notice-bar__inner">
    <svg class="notice-bar__icon icon" aria-hidden="true" focusable="false"><use href="/assets/icons/sprite.svg#warning"></use></svg>
    <span class="notice-bar__label">예고</span>
    <p class="notice-bar__message">
      <a class="notice-bar__link" href="/notice/○○">○월 ○일 00:00~06:00 ○○ 시스템 점검으로 온라인 신청이 멈춥니다</a>
    </p>
  </div>
</section>
```

- **긴급도**: 스니펫의 긴급도 표를 따른다(상 `--danger`·중 `--warning`·하 기본, 레이블과 아이콘 포함). 긴급도는 레이블 텍스트로 전한다. 아이콘은 `aria-hidden`이다 — KRDS도 레이블이 뜻을 전하므로 아이콘에 대체 텍스트를 주지 않는다. 레이블 문구는 기관 용어(`contentSources`)로 바꿀 수 있지만, 색만으로 긴급도를 전하지 않는다.
- **역할**: 라이브 영역을 쓰지 않는다(`role="alert"`·`role="status"`·`aria-live` 없음). 로드 때 이미 있는 정적 안내이기 때문이다.
- **role="banner"**: KRDS 접근성 지침은 긴급 공지 섹션에 `role="banner"`를 준다. 카탈로그는 `section[aria-label]` 이름 있는 영역이다. `role="banner"`를 붙이면 `header#header`와 banner 랜드마크가 둘이 되고, main 안에 banner가 들어가 랜드마크 구조가 어긋난다. 그래서 적용 여부는 UX팀 KRDS 대조 안건으로 올렸다. 결정 전에는 카탈로그 그대로 쓴다.
- 문구·주소·시각은 `contentSources`에서만 가져온다(R-23).
- **금지**: 닫기·숨기기·접기 버튼, 2개 이상 동시 노출, 자동 전환·롤링, 일반 공지·홍보·입력 피드백 용도, header 앞이나 건너뛰기 링크 앞 배치, 기간이 지난 공지 방치, `alert`로 만들기.

#### KS-01 메인 비주얼 — intro

- **목적**: 사이트 정체성과 홍보·부가 정보를 첫 화면에 보인다. 1순위 과업은 캐러셀 밖 정적 블록에 둔다(KR-M02).
- **필수 요소**: 슬라이드별 HTML 제목과 링크. 페이지 h1은 하나다 — 슬라이드 제목을 h1으로 쓰지 않는다.
- **캐러셀 규칙**: §8 「캐러셀 규칙」(정본 `src/snippets/carousel.md`). 슬라이드는 5장 이내다.
- **변주**: 정지 이미지(`hero-bleed`), 이미지 슬라이더(`carousel`), 분할(`section-media`), 텍스트 히어로. 영상은 expressive에서만 쓰고 자동 재생하지 않는다(KRDS). 사용자가 재생하고, 재생·정지 컨트롤은 키보드로 조작한다(§8).
- **접근성**: 이미지 위 텍스트는 스크림(`hero-bleed--scrim`) 위에서 대비 4.5:1을 실측한다.
- **금지**
  - 문구를 이미지에 넣기(alt로 대신해도 안 된다)
  - 6장 이상 슬라이드, 「전체 보기」 모달
  - 모든 슬라이드에 같은 카피 반복
  - 어두운 오버레이 + 중앙 흰 문구 + 스크롤 화살표만 있는 구성(`art-direction.md` §10 안티패턴 7)

#### KS-02 팝업존(본문 안 알림판) — notice

- **목적**: 기간 한정 행사·모집 안내를 본문 안에 모은다. 진입 모달을 대신한다. 긴급 정보는 KS-00으로 보낸다.
- **기본 마크업**: 항목마다 HTML 제목, 기간(`time[datetime]`), 링크 텍스트, 장식 이미지(`alt=""`)를 둔다.
- **최신 정보**: 기간이 지난 항목은 내린다(KRDS 방문 패턴 「최신의 정확한 정보」). 최신 항목을 앞에 둔다.
- **발주처가 이미지 배너만 줄 때**: 이미지 속 문구를 HTML 텍스트(제목·기간·대상·링크)로 다시 쓰고, 글자 없는 배경 이미지를 요청한다. 그래도 안 되면 슬라이드에 넣지 않고 정적 링크 목록으로 둔다. 텍스트 이미지 슬라이드 예외는 없다.
- **컨트롤**: §8 캐러셀 규칙. 5건 이내 — 6건 이상이면 목록 + 전체 목록 페이지 링크.
- **구분**: 모든 레시피에서 캐러셀 조건을 충족할 때만 권장이다(KP-05 ②). 관찰 28/96(29%, 재집계).
- **금지**: 진입 모달 다중 띄우기, 장식용 「New」 배지, 기간이 지난 항목 방치, 중요한 공지를 팝업존에만 두기, 1순위 과업 section에 넣기(KR-M03).

#### KS-03 퀵링크(자주 찾는 서비스) — list

- **필수 요소**: 카탈로그 아이콘(`aria-hidden`)과 보이는 텍스트 레이블을 함께 둔다. 4~12개, 실제 URL로 연결한다.
- **접근성**: `ul`로 만든다. `list-style: none`이면 `role="list"`를 준다. 링크 전체를 44px 이상 터치 영역으로 만든다. 아이콘만 있는 링크는 만들지 않는다.
- **금지**: 텍스트를 넣은 아이콘 이미지, 12개를 넘는 단일 그리드, 기능 없는 장식 아이콘 남발.

#### KS-04 공지 목록(최신글) — notice

- **필수 요소**
  - 게시판이 2개 이상이면 KRDS 탭을 쓴다. 모든 탭이 `Tab`으로 닿고 `Enter`·클릭으로 고른다. 탭은 6개 이하이고 비활성 탭은 없다(KR-M05, 정본 `src/snippets/tab.md`).
  - 탭당 4~5건을 최신순으로 두고, 패널마다 「<게시판명> 더보기」 링크를 둔다.
  - 날짜는 `time[datetime]`이다.
- **접근성**: 새 글 표시는 보이는 텍스트나 접근 가능한 이름으로 준다. 말줄임 제목은 `title` 속성에만 기대지 않는다.
- **금지**: 탭마다 똑같은 「더보기」 텍스트, 정지할 수 없는 세로 자동 롤링, 페이지 이동 링크 묶음을 탭으로 만들기.

#### KS-05 소식 카드 — list

- **필수 요소**: 제목(2줄 이내)과 날짜(`time[datetime]`), 최신순. 카드 하나에 링크 하나. 썸네일 비율은 섹션 안에서 하나로 통일한다(`art-direction.md` §7). 분류는 `badge--neutral` 텍스트다. 상품 카드(커머스)는 상품명·가격 텍스트·혜택 배지를 같은 구조로 둔다.
- **금지**: 카드 그리드 섹션 연속·페이지당 3개 이상(R-25), 카드 안 카드, CSS에 없는 카드 element 지어내기(R-29), 변형 없는 `.badge`(위험색)로 분류 표시.

#### KS-06 서비스·분야 — content 또는 list

- **변주**: 분야 탭 + 링크 목록, 또는 사업 분야 소개(`section-media` 1왕복).
- **금지**: 카드 중첩, 텍스트를 넣은 아이콘 이미지.

#### KS-07 일정(프로그램·행사) — data

- **필수 요소**: 유형·월 필터(탭, 또는 `select` + 적용 버튼), 상태 텍스트 배지, 기간·장소·상세 링크. 상태 배지는 진행 중·접수 중 `badge--success`, 예정 `badge--info`, 종료·마감 `badge--neutral`이다.
- **KRDS 필터 규칙**: 날짜·기간 필터는 범위 입력으로 받는다. 적용 조건·조건 수·결과 수·개별 해제를 화면에 보이고, 프로그램으로도 알린다. 결과 수는 `aria-live="polite"`다.
- **달력**: 정기적이고 날짜 밀도가 높을 때만 쓰고, 같은 내용의 목록을 함께 둔다(KRDS 달력 — 한 달 2건 이하면 부적합).
- **금지**: 이미지로만 된 달력, 종료된 행사 방치, 색만으로 상태 표시.

#### KS-08 수치 — data

- **필수 요소**: 수치, 단위, 항목명, 출처, 기준일.
- **기본값**: 정적 숫자. 카운트업은 §8 조건에서만.
- **금지**: 출처 없는 수치(R-23, `art-direction.md` §10 안티패턴 5).

#### KS-09 검색 밴드 — search

- `label`을 둔다. placeholder로 label을 대신하지 않는다.
- 검색 버튼은 보이는 텍스트(「검색」)로 이름을 준다.
- 추천 검색어는 실제 운영 데이터가 있을 때만 둔다.
- 결과 화면은 KR-S13을 따른다.

#### KS-10 미디어(영상·사진·SNS) — content

- 영상은 파사드로 둔다(썸네일 + 재생 버튼, 누르면 iframe 로드). iframe에 `title`을 준다. 자동 재생하지 않는다(KRDS).
- 정보를 전하는 영상은 캡션과 화면 해설 또는 설명적 원고를 둔다(KRDS 접근 가능한 미디어).
- SNS는 정적 썸네일과 채널 링크로 둔다. 임베드를 한꺼번에 로드하지 않는다.
- 외부로 이동하거나 새 창이 열리면 보이는 단서와 접근 가능한 이름으로 예고한다(§8).

#### KS-11 관련 기관 — list

- **구성**: 로고 이미지(`alt`=기관명)와 링크, 또는 텍스트 링크 목록.
- **변주**: 정적 목록, 그룹별 `accordion`, 수동 넘김 캐러셀(자동 회전 기본 끔, §8 캐러셀 규칙).
- **금지**: 무한 마키(`art-direction.md` §10 안티패턴 8), select 선택 즉시 이동(WCAG 3.2.2), alt가 빈 로고 링크.

#### KS-12 배너·CTA·오시는 길 — content

- 배너·CTA는 한 섹션에 하나만 두고, 문구는 HTML로 쓴다. 버튼 레이블은 동사형이다.
- 오시는 길은 주소·교통 정보를 텍스트로 적는다. 지도가 없어도 정보가 완결돼야 한다. 지도 iframe에 `title`을 준다.

## 4. 서브 페이지 골격

`pageType`이 `sub-content`·`board-list`·`board-detail`인 페이지의 골격이다. KRDS 사이드 메뉴·건너뛰기 링크·브레드크럼 규정(D1, 검증 보정 반영)과 상세 정보 확인 패턴을 따른다. page shell 계약(`main` 직계는 section, section은 `.container` 포함)은 바꾸지 않는다.

```
a.skip-to-content[href="#contents"]      본문 바로가기 — 문서 첫 요소, 건너뛰기 링크 3개 이내 (R-14는 §3.2)
(공식 배너 — publicIdentity: required, 카탈로그 반입 후)
header#header.site-header
main#main
  (조건부) section.section.section--intro[aria-label]   서브 비주얼 띠 — h1 없음
  section.section.section--content[aria-labelledby="page-title"]
    .container
      [사이드 메뉴]      side-navigation 반입 후 — 1024px 이상 2단, 미만 숨김. DOM에서도 본문 앞(CSS order로 바꾸지 않는다)
      [페이지 도구]      #contents 밖, 브레드크럼 앞
      nav.breadcrumb     바로 다음이 #contents — 브레드크럼과 h1 사이에 다른 요소 없음
      div#contents[tabindex="-1"]   ← 본문 바로가기 목적지
        h1#page-title    목적지의 첫 요소
        콘텐츠 정보(요약) — 담당부서·등록일·최종 변경일 (KR-S11 ①)
        [콘텐츠 내 탐색]  KR-S12
        본문(h2·h3 …)
        콘텐츠 정보(전체) — 작성자·출처·저작권·변경 이력 (KR-S11 ①)
        (조건부) 만족도 (KR-S11 ②)
footer#footer.site-footer
```

`section--content` 안쪽 조합 예시는 다음과 같다(page shell 전체는 위 골격).

```html
<section class="section section--content" aria-labelledby="page-title">
  <div class="container">
    <div role="group" aria-label="페이지 도구">
      <button type="button" class="btn btn--tertiary btn--small">주소 복사하기</button>
      <button type="button" class="btn btn--tertiary btn--small">인쇄하기</button>
    </div>
    <nav class="breadcrumb" aria-label="브레드크럼">
      <ol class="breadcrumb__list">
        <li class="breadcrumb__item"><a href="/">홈</a></li>
        <li class="breadcrumb__item"><a href="/○○">○○</a></li>
        <li class="breadcrumb__item" aria-current="page">○○ 안내</li>
      </ol>
    </nav>
    <div id="contents" tabindex="-1">
      <h1 id="page-title">○○ 안내</h1>
      <dl class="list--structured">
        <div class="list__row"><dt>담당부서</dt><dd>○○과</dd></div>
        <div class="list__row"><dt>최종 변경일</dt><dd><time datetime="2026-10-01">2026. 10. 1.</time></dd></div>
      </dl>
      …
    </div>
  </div>
</section>
```

- **R-14 개정이 이 골격의 선행 조건이다.** 개정 내용은 다음과 같다. `html-page-contract.json` 선택자를 「`main#main` 또는 main 안 `#contents`를 가리키고, 목적지 하위에 사이드 메뉴·브레드크럼·페이지 도구가 없을 것」으로 바꾼다. `check-html-structure.js`와 단위 테스트, `rules.json` R-14 예시, `html-semantics.md` §0.1도 함께 고친다. 개정 전 처리는 §3.2를 따른다.
- 메인 페이지처럼 main 안에 반복 탐색 영역이 없으면 `#main`을 그대로 쓴다.
- 간격은 KRDS 레이아웃 간격 토큰(`krds-source.md` 레이아웃 간격)을 권장 간격으로 쓴다.
- 예시 값(○○·날짜)은 형식 예시다. 실제 값은 `contentSources`에서만 가져온다(R-23).

| 번호 | 규칙 | 근거 |
|------|------|------|

**캐러셀 규칙** — 메인 비주얼·팝업존·관련 기관 공통. 정본은 `src/snippets/carousel.md`다.

- 슬라이드는 5개 이내다. 6건 이상이면 캐러셀 대신 목록과 전체 목록 페이지 링크를 쓴다. 「전체 보기」 모달 변형은 두지 않는다.
- 자동 회전이면 정지/재생 버튼이 캐러셀의 **첫 상호작용 요소**다.
- 키보드 초점이 들어오면 정지하고, 사용자가 재생을 누르기 전에는 다시 돌지 않는다. 마우스를 올리면 멈춘다.
- 보이지 않는 슬라이드는 초점·보조기기에서 뺀다.
- 슬라이드가 1개면 컨트롤을 숨긴다. 1024px 미만은 분수형 식별자, 1024px 이상은 도형형 식별자다.
- 컨트롤과 식별자가 슬라이드 내용을 가리지 않는다. 컨트롤은 44×44px 이상이다.
- `prefers-reduced-motion: reduce`면 자동 회전을 시작하지 않는다(R-22).
- 전환 간격은 5초 이상이다 — **infoUX 판단값**(KRDS는 「적절한 전환 간격」만 정한다).

**카운트업 조건(D7)** — KRDS 직접 규정 없음. 캐러셀·스플래시·자동 재생 규정을 준용한 infoUX 판단이다.

- 수치 블록의 기본값은 정적 숫자다. 카운트업은 expressive 등급에서만 쓴다. utility·restrained와 페이지 단위 강등 화면(폼·결제·인증·오류·검색 결과)에서는 쓰지 않는다.
- HTML에는 최종값을 텍스트로 둔다. JS가 실패해도 최종값이 보인다. 애니메이션 중인 숫자는 `aria-hidden`이다. 최종값은 같은 `dl` 안 `sr-only` 텍스트로 두고 `aria-live`는 쓰지 않는다.
- 뷰포트에 처음 들어올 때 1회, 1,000ms 이하로만 재생한다(KRDS 스플래시 「1,000ms 이내」 준용). 반복·재트리거를 하지 않는다.
- `prefers-reduced-motion: reduce`면 재생하지 않는다. 색·밝기 점멸을 덧붙이지 않는다. `tabular-nums`로 자릿수 폭을 고정한다.
- 출처·기준일이 없는 수치는 카운트업 여부와 무관하게 만들지 않는다.

## 9. AI 슬롭 방지 — 한국형 메인

규정은 지켰는데 「AI가 만든 티」가 나는 메인의 증상과, 그 대신 할 것이다. `art-direction.md` §10 안티패턴과 겹치는 항목은 그 번호로 링크한다. 납품 전 `art-direction.md` §9 리뷰 체크리스트(KRDS 대조 포함)와 함께 1회 점검한다.
