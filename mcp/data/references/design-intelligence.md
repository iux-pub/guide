# 디자인 판단 절차 — 규칙을 지킨 무개성을 넘어서

규칙 검사를 통과한 화면이 여전히 "구린" 이유는 대부분 판단 순서를 건너뛴 데 있다. 제품 성격을 정하지 않은 채 컴포넌트를 쌓으면 화면마다 다른 표면 언어가 섞이고, 위계가 약해지며, 빈 칸이 생긴다. 이 문서는 구현 전에 거치는 판단 순서, 디자인 다이얼 세 가지, 스타일 허용표, 납품 전 품질 점검을 정한다.

> 출처 — 판단 순서·다이얼·우선순위 표·전문가 품질 항목은 ui-ux-pro-max 스킬(Next Level Builder, MIT, github.com/nextlevelbuilder/ui-ux-pro-max-skill, 검토 커밋 28327f2)을 infoUX 맥락으로 옮겨 다시 쓴 것이다. 원 스킬의 스타일·팔레트·서체 추천은 해외 SaaS 기준이라 그대로 쓰지 않는다. **KRDS와 infoUX 규칙(rules.json)이 언제나 우선한다.** 애매하면 KRDS를 따른다.

---

## 1. 판단 순서

구현 전에 아래 여덟 단계를 Task Contract와 함께 적는다. 앞 단계가 뒤 단계를 묶는다.

| 단계 | 정할 것 | infoUX 정본 |
|------|---------|-------------|
| 1. 제품 유형 | 사이트 유형과 1순위 과업 | `profile`, `primaryTask` (project-profiles.md) |
| 2. 패턴 | 섹션 순서와 각 섹션의 역할 | 한국형 메인·서브 레시피 (korean-web-patterns.md) |
| 3. 스타일 | 표면 언어 하나 — §3 허용표에서 고른다 | 이 문서 §3 |
| 4. 다이얼 | 변화도·모션·밀도 1~10 | `designDials` (이 문서 §2) |
| 5. 색 | 팔레트 프리셋, point 색 사용처 | art-direction.md §4 |
| 6. 서체 | 타이포 페어링, 크기 대비 | art-direction.md §2·§3 |
| 7. 효과 | 반경·그림자·스크림·모션 수치 | R-34·R-35, interaction-timing |
| 8. 안티패턴 | 이 화면에서 특히 경계할 것 3개 | art-direction.md §10 + 이 문서 §5 |

- 각 단계의 결정은 한 줄 근거와 함께 적는다. "허용되니까"는 근거가 아니다.
- 한 페이지 안에서 스타일은 하나다. 섹션마다 다른 카드 처리를 쓰지 않는다(§4-1).

## 2. 디자인 다이얼

세 다이얼은 표현 등급 안에서 수위를 정하는 손잡이다. 표현 등급(art-direction.md §1)이 상한이고, 다이얼은 그 안의 위치다. Task Contract `designDials`에 적는다.

| 다이얼 | 1~3 | 4~6 | 7~10 |
|--------|-----|-----|------|
| 변화도 `variance` — 배치의 비대칭·크기 대비 | 중앙 정렬, 균등 격자 | 좌정렬, 2:1·1:2 비대칭 격자, 큰 제목과 본문의 뚜렷한 대비 | 겹침·대각 배치·과장된 크기 대비 |
| 모션 `motion` — 장식·진입 모션의 양 | 상태 피드백만 | 호버 150~250ms, 한 번만 나타나는 진입 페이드 | 스크롤 연출, 시차, 순차 등장 |
| 밀도 `density` — 정보량과 여백 | 넓은 여백, 섹션당 항목 적게 | 표준 | 촘촘한 목록·표, 관리자 화면 |

등급별 상한:

| 등급 | variance | motion | density |
|------|----------|--------|---------|
| 기능형 `utility` | ≤3 | ≤2 | 5~9 |
| 절제형 `restrained` | ≤6 | ≤4 | 4~7 |
| 표현형 `expressive` | ≤8 | ≤6 | 3~7 |

- motion 7 이상은 infoUX에서 쓰지 않는다. 스크롤 하이재킹·시차·무한 반복은 R-22·R-33과 안티패턴 8번이 막는다.
- variance를 올려도 KRDS 그리드·브레이크포인트·반경 상한은 그대로다. 비대칭은 열 비율과 크기 대비로 만든다.
- density는 R-49(공공 화면 섹션 여백 상한)와 함께 본다.

## 3. 스타일 허용표

ui-ux-pro-max의 스타일 목록 가운데 KRDS와 함께 쓸 수 있는 것만 남겼다.

| 스타일 | 판정 | infoUX에서 쓰는 법 |
|--------|------|---------------------|
| Accessible & Ethical | 기본 | 모든 프로필의 바탕. 대비 4.5:1, 보이는 초점, 44px 터치, 감소 모션 존중 |
| Minimalism & Swiss | 권장 | 격자·여백·크기 대비로 위계를 만든다. 테두리 상자 대신 가는 구분선과 여백으로 묶는다 |
| Editorial Grid | 절제형 이상 | 큰 사진과 비대칭 격자. 본문 세리프·드롭캡·다단 본문은 쓰지 않는다(KRDS 본문 서체) |
| Bento Grid | 절제형 이상 | 크기가 다른 칸으로 주요 항목을 묶는다. 칸 수 3~5, 빈 칸을 남기지 않는다 |
| Flat Design | 허용 | 그림자 없는 면 구분. 기능형 화면의 기본 |
| Glassmorphism·Aurora·Neumorphism·Claymorphism·Vibrant gradient | 금지 | R-34(장식 효과)·R-35(반경·그림자)와 충돌 |
| Brutalism·Retro film·Cyberpunk 계열 | 금지 | 공공·기관 신뢰 톤과 충돌, 대비·가독 위험 |

## 4. 전문가 품질 점검 — 규칙 검사가 잡지 못하는 것

검사기는 위반을 잡지만 어색함은 못 잡는다. 아래는 "구리다"는 평가의 흔한 원인이다. 납품 전 렌더 화면(375·768·1024·1440)을 보며 확인한다.

### 4-1. 표면 언어
- [ ] 한 페이지의 카드·패널 처리는 두 가지 이하다(예: 사진 카드 + 구분선 목록). 테두리 상자·회색 상자·검정 반투명 상자·옅은 색 상자를 섞지 않는다.
- [ ] 그림자는 KRDS 단계 하나만 쓴다. 떠 있는 요소(히어로에 겹친 패널 등)에만 둔다.
- [ ] 아이콘은 한 가족·한 굵기·한 크기 단계다. 채움형과 선형을 같은 위계에 섞지 않는다.

### 4-2. 위계와 격자
- [ ] 화면마다 주 행동(primary 버튼)은 하나다. 나머지는 secondary·text다.
- [ ] 섹션 제목과 본문의 크기 비가 2배 이상이다(예: 4rem ↔ 1.7rem). 비슷한 크기의 굵은 글자가 여러 단계로 흩어지지 않는다.
- [ ] 격자에 빈 칸이 없다. 사진이 없는 항목을 사진 칸 사이에 빈 패널로 끼우지 않고, 목록이나 다른 행으로 뺀다.
- [ ] 여백 단계는 4·8의 배수로 정한 몇 단계뿐이다. 섹션 간격·블록 간격·요소 간격이 각각 일정하다.
- [ ] 큰 화면에서 본문 줄이 끝까지 늘어나지 않는다(설명 문단 최대 폭 지정).

### 4-3. 사진
- [ ] 사이트당 사진 톤은 하나다(art-direction.md §7). 어둡고 탁한 사진을 첫 화면에 두지 않는다.
- [ ] 사진 위 글자는 스크림 위에서 대비를 실측한다. 사진마다 검정 상자를 얹기보다 사진 아래 캡션으로 빼는 편이 깨끗하다.
- [ ] 이미지에 `width`·`height` 또는 `aspect-ratio`를 둬 레이아웃 밀림을 막고, 첫 화면 밖 이미지는 `loading="lazy"`다.

### 4-4. 상호작용
- [ ] 누를 수 있는 요소는 모두 `cursor: pointer`이고, 호버·초점·누름 상태가 보인다. 상태 변화가 레이아웃을 밀지 않는다(색·밑줄·그림자로).
- [ ] 호버 전환은 150~250ms이고 `prefers-reduced-motion`에서 꺼진다.
- [ ] 터치 대상 사이 간격이 0.8rem 이상이다.
- [ ] 숫자가 줄 맞춤되는 곳(날짜 열·통계)은 `tabular-nums`다.

## 5. 우선순위

충돌할 때는 위가 이긴다. KRDS는 이 표보다 위다.

1. 접근성 — 대비, 초점, 대체 텍스트, 키보드, 제목 단계
2. 터치·상호작용 — 44px, 간격, 누름 피드백
3. 성능 — 이미지 크기·지연 로딩, 서체 로딩
4. 스타일 일관성 — §3·§4-1
5. 레이아웃·반응형 — 모바일 우선, 가로 넘침 없음
6. 서체·색 — 한글 조판, 팔레트
7. 모션 — 등급 예산 안
8. 폼·피드백
9. 내비게이션
10. 차트·데이터

## 6. 참고 검색 도구(선택)

ui-ux-pro-max 원본을 받아 둔 경우 `scripts/search.py`로 스타일·랜딩·UX 지침을 검색할 수 있다. 결과는 **참고 자료**이며 그대로 적용하지 않는다.

```bash
python search.py "<제품 유형 키워드>" --design-system --variance 4 --density 5
python search.py "<주제>" --domain ux
```

- 결과의 색 hex·Google Fonts 주소는 쓰지 않는다. 색은 프리셋, 서체는 카탈로그(R-01·R-26).
- 결과가 0건이면 키워드를 바꿔 한 번 더 찾고, 그래도 없으면 "일치 없음"이라고 적고 이 문서 기준으로 정한다.
- 내려받은 저장소는 별도 폴더에 두고, 파이썬은 그 폴더 밖에서 실행한다.
