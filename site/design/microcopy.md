버튼, 오류 메시지, placeholder, 툴팁, 빈 화면 문구를 쓰는 기준. 화면에 글자가 들어가는 모든 작업에 적용한다.

> **정본 관계** — KRDS(컴포넌트·패턴·타이포그래피 지침) → `contracts/art-direction.json`(MCP `get_art_direction`)·`contracts/profiles.json`(`get_profile`) → 이 문서. 충돌하면 앞선 것이 이긴다. 이 문서의 표와 예시는 참고 자료다.

문체는 **합쇼체 사실 서술**이다(「저장했습니다」「등록된 공지가 없습니다」). 해요체(「저장됐어요」), 번역투(「지금 시작하세요」), 2인칭 「당신」, 공공 화면의 느낌표는 쓰지 않는다(R-43·R-44, `references/art-direction.md` §8). 금지 어휘는 `contracts/copy-lexicon.json`에 있다.

## 에러 메시지 3-Part 공식

**무엇이 잘못됐는지 + (왜) + 어떻게 해결하는지**

오류 메시지는 이 세 부분을 담는다. 원인을 알 수 없으면 「왜」는 뺀다.

| 잘못된 예 | 올바른 예 |
|-----------|-----------|
| "오류가 발생했습니다" | "저장하지 못했습니다. 네트워크 연결을 확인한 뒤 다시 시도해 주십시오." |
| "잘못된 입력입니다" | "이메일 주소 형식이 올바르지 않습니다. name@example.kr 형식으로 입력해 주십시오." |
| "에러" | "파일 크기가 10MB를 넘습니다. 10MB 이하 파일을 선택해 주십시오." |

### 작성 원칙

- **사용자를 탓하지 않는다** -- 「잘못 입력했습니다」가 아니라 「형식이 올바르지 않습니다」처럼 상태를 서술한다
- **기술 용어 금지** -- Error 500, null reference 같은 내부 오류 코드를 노출하지 않는다
- **다시 시도할 경로 제공** -- 가능하면 「다시 시도」 버튼을 함께 둔다
- **한두 문장**으로 끝낸다
- **사용자 입력 유지** -- 오류가 나도 입력값을 지우지 않는다

## 버튼 텍스트 규칙

버튼은 실행될 기능을 알 수 있는 **동사형**으로 쓴다(「신청하기」「파일 내려받기」「변경사항 저장」). 명사형은 KRDS 예외(완료·닫기·취소·추가·삭제 같은 일반 작업, 동사로 쓰면 길이·해석에 문제가 생기는 경우)에만 쓴다(KRDS 버튼 component_05_02).

| 금지 | 대체 | 이유 |
|------|------|------|
| 확인 | 저장, 적용, 닫기 | 무엇을 확인하는지 알 수 없다 |
| 예 / 아니요 | 삭제 / 취소 | 버튼만 읽어도 결과를 알 수 있어야 한다 |
| 신청하세요, 확인해 보세요 | 신청하기, 결과 확인 | 「~하세요」로 끝나는 버튼은 R-43 오류 |
| 더보기 | 공지사항 더 보기 | 목적지를 말하지 않는 이름(R-30) |
| VIEW MORE, SUBMIT | 한국어 동사형 | 한국어 화면의 영문 전용 레이블(R-45) |

### 추가 규칙

- **결과를 밝힌다**: 「저장」보다 「변경사항 저장」이 분명하다
- **대상을 밝힌다**: 「삭제」보다 「게시글 삭제」 — 되돌릴 수 없는 동작은 무엇을 지우는지 쓴다
- **짧게 쓴다**: 두세 어절 안에서 끝낸다. 버튼 안에서 줄을 바꾸지 않는다

### 삭제 확인 대화상자

```
제목: 게시글 삭제
내용: 삭제한 게시글은 복구할 수 없습니다. 첨부 파일도 함께 삭제됩니다.

[취소]  [게시글 삭제]
```

## 톤 매핑 테이블

사이트 유형(프로필)마다 문체를 고정한다. 정본은 `references/art-direction.md` §1 프로필 표의 카피 톤 열이다.

| 사이트 유형 | 문체 | 예시 |
|-------------|------|------|
| **일반사이트** | 합쇼체 기본. 직역체·2인칭 「당신」 금지 | "문의를 접수했습니다." |
| **공공서비스** | 합쇼체 고정. 느낌표 금지. KRDS 용어 우선 | "신청이 접수되었습니다." |
| **공공기관** | 합쇼체 고정. 성과 홍보 어조 금지 — 사실 서술 | "2026년 사업 공고를 게시했습니다." |
| **CMS·관리자** | 개조식. 문장 최소화 | "저장 완료" |
| **커머스·예약** | 합쇼체 기본. 근거 없는 최상급 금지. 가격·기간을 먼저 | "예약이 완료되었습니다. 10월 25일 14시" |

### 일관성 규칙

- **같은 개념에는 같은 단어**: 「삭제」와 「제거」를 섞지 않는다
- **경어 수준 통일**: 한 화면에서 합쇼체와 해요체를 섞지 않는다(R-44)
- **성공 메시지는 짧게**: 일상적인 저장·등록에 축하 표현을 쓰지 않는다

## 플레이스홀더 규칙

placeholder는 **레이블을 대신하지 않는다**. 입력 예시만 둔다(R-50).

### 허용 사용

| 사용 목적 | 예시 |
|-----------|------|
| 형식 예시 | `name@example.kr` |
| 값 예시 | `홍길동` |
| 표기 예시 | `2026.10.25` |

### 금지 사용

| 금지 패턴 | 이유 |
|-----------|------|
| 「프로젝트명을 입력하세요」「내용을 입력하세요」 같은 빈 안내 | 레이블이 이미 말한 것을 되풀이한다(R-50) |
| 레이블 없이 placeholder만 사용 | 입력을 시작하면 사라진다 |
| 긴 설명문, 필수 조건 | 입력 중에 보이지 않는다 — `form-field__hint`에 쓴다 |

- 입력 조건(글자 수, 형식)은 placeholder가 아니라 보조설명(`form-field__hint`)에 쓰고 `aria-describedby`로 연결한다.
- placeholder 글자색은 카탈로그의 `--color-text-disabled`다. 흐리게 보이므로 꼭 읽어야 하는 정보를 담지 않는다.

## 빈 상태 구조

제목은 필수이고, 버튼은 **사용자가 할 수 있는 다음 행동이 있을 때만** 둔다. [UI 상태 패턴](/design/ui-states/) 「빈 상태」와 같은 기준이다.

```
제목: 등록된 [콘텐츠]가 없습니다            -- 필수. 사실 문장
설명: [콘텐츠]를 등록하면 여기에 표시됩니다.  -- 선택

[콘텐츠 등록]                              -- 다음 행동이 있을 때만
```

### 유형별 카피

| 유형 | 제목 예시 | 버튼 |
|------|-----------|------|
| **데이터 없음** | "등록된 공지가 없습니다" | (등록 권한이 있으면) 공지 등록 |
| **검색 결과 없음** | "'키워드'에 대한 검색 결과가 없습니다" | 검색어 지우기 |
| **필터 결과 없음** | "조건에 맞는 항목이 없습니다" | 필터 초기화 |
| **불러오기 실패** | "목록을 불러오지 못했습니다" | 다시 시도 |
| **권한 없음** | "이 페이지를 볼 수 있는 권한이 없습니다" | 로그인, 권한 신청 |

빈 상태 제목은 사실을 알리는 문장으로 쓰고, 행동은 버튼에 맡긴다. 「~해보세요」「지금 시작하세요」 같은 재촉형 문구와 2인칭 「당신」은 R-43이 검출한다 — 어휘는 `contracts/copy-lexicon.json`.

## 숫자 포맷

| 유형 | 형식 | 비고 |
|------|------|------|
| 날짜 | `2026.10.25` 또는 `2026년 10월 25일` | `<time datetime="2026-10-25">`로 감싼다. 한 사이트에서 한 가지 형식만 쓴다 |
| 상대 시간 | `2시간 전` | `datetime`에 실제 시각을 넣는다 |
| 기간 | `2026.10.25 ~ 2026.11.08` | 접수·모집 기간은 시작과 끝을 모두 쓴다 |
| 큰 숫자 | `1,200,000` 또는 `120만` | 세로로 정렬되는 숫자는 `tabular-nums` |
| 파일 크기 | `1.4MB`, `320KB` | |
| 진행률 | `75%` | `progress` 레이블 줄에 글자로 쓴다 |

수치에는 기준일과 출처를 함께 쓴다. 출처 없는 통계는 싣지 않는다(R-23).
