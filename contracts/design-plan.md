# 디자인 기록 서식

메인·랜딩 페이지를 만들 때 이 서식을 프로젝트의 `docs/design-plan.md`로 복사해 채운다. 절차는 `references/design-intelligence.md`가 정한다. 납품 검사(`npm run check:release`)는 메인 페이지가 있는 프로젝트에 이 파일과 아래 네 제목, 그리고 「사람 판정」의 「승인」이 있는지 확인한다.

서브·게시판·폼만 만드는 작업에는 쓰지 않는다.

이 기록은 디자인을 설명하거나 정당화하는 곳이 아니다. 생성에 준 브리프와 재료, 바닥 교정에서 바꾼 것, 사람의 판정만 남긴다.

```markdown
# 디자인 기록 — <사이트 이름>

## 브리프
기관: <이름 · 하는 일 한 줄>
1순위 과업: <첫 화면이나 바로 아래에서 끝나야 하는 일>
사용자: <누가 주로 들어오는가>
기준 수준: <발주자 답 원문 — 견줄 사이트가 있으면 이름>
피할 것: <발주자 답 원문>

## 재료
- 콘텐츠: <contentSources 경로 — 메뉴·공지·사업명의 출처>
- 사진: <파일 · 출처 · 라이선스 | 이미지 자리와 교체 목록 경로>

## 교정 기록
- <R-번호 또는 체크리스트 항목> — <어디를> — <무엇을 어떻게 바꿨나>
- 예외 후보: <검사 규칙과 디자인이 부딪친 곳과 exceptions[] 항목 | 없음>

## 사람 판정
판정: <대기|승인|불통과> — <판정한 사람, 날짜, 사유 원문>
```

- 「교정 기록」은 바꾼 것이 없으면 「없음」이라고 적는다.
- 「사람 판정」은 운영자·발주자가 정한다. 에이전트가 「승인」을 대신 채우지 않는다. 다시 판정받으면 아래에 「판정:」 줄을 더한다 — 검사는 마지막 줄을 읽는다.
